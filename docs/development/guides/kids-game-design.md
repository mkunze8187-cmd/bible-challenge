# Kids Game Design Guide

## Learning pattern
Agon kids games should normally follow:

**Hear it -> Play it -> Say it -> Take it Home**

- **Hear it:** Scripture is visible/read through BibleTextService and clearly distinguished from explanation.
- **Play it:** gameplay reinforces one or more concrete learning ideas.
- **Say it:** age-appropriate verse/reference recall or repetition.
- **Take it Home:** optional Dig Deeper material for parents/families.

## Age profiles
### Preschool 3–5
Favor pictures, narration, large targets, repetition, short rounds, adult co-play, immediate feedback and minimal/no time pressure. Numeric ranking is optional and often unnecessary.

### Kids 6–10
Add reading, ordering, matching, recall, simple strategy, timed options and discussion prompts while preserving accessible alternatives.

## Scripture and application
Never rewrite an invented scenario as Scripture or invent dialogue for biblical figures and present it as biblical text. Application activities may illustrate a concept, but UI/help should distinguish `Scripture`, `Explanation`, and `Application` content types.

Recorded biblical events do not change because a child wins/loses a game. Game state may affect score, presentation, attempts or activity completion—not canonical outcomes.

## Spiritual-concept scoring
Do not score, meter or rank a child's faith, humility, salvation, righteousness, prayer quality, God's favor, blessing, obedience worth or spiritual value. Score objective game performance only: matching, recall, ordering, timing, puzzle completion, etc.

Do not imply a wrong answer means Jesus rejects the player, God is disappointed, or the child lacks faith. Retry/review should be supportive and factual.

## Reusable mechanics first
A kids theme should normally consume shared mechanics. Examples:
- Noah animal pairs -> Memory Matching capability + Noah content/presentation;
- verse puzzles -> Ordering/Challenge;
- path activities -> Journey/Board primitives;
- spinner/dice -> Randomizer;
- cards -> Card/Deck.

Do not create a theme-specific engine where a content/profile/adapter is sufficient.

## Pressure and failure
Preschool defaults should avoid punitive countdowns, threatening loss meters and elimination. Older profiles may offer optional timers/attempt goals when pedagogically appropriate. A thematic pressure visual must not imply the player changes a recorded biblical event.

## Accessibility
Kids experiences should provide large-target and keyboard/controller access, semantic labels, non-color-only cues, reduced motion, configurable reveal/read time, narration where practical, and alternatives to sound-only or image-only identification.

## Multiplayer
Prefer cooperative/family modes when the teaching concept would become distorted by competition. Competitive play is appropriate for objective mechanics, but never rank players on spiritual traits.

## Help and parent material
Each kids game should have:
- a very short How to Play;
- Scripture references;
- age/profile notes;
- parent/host explanation of the learning goal;
- Dig Deeper prompts;
- clear labeling where game scenarios are illustrative application rather than biblical events.
